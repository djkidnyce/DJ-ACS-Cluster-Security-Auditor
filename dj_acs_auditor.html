Getting data out of ACS

This page does not talk to ACS or to your cluster, on purpose. A page opened from a file has a null origin, and neither ACS Central nor the OpenShift API sends a header that permits it, so an in browser connector could never work from here. Building one anyway would mean asking you to paste a live ACS API token into a browser tab in exchange for a request the browser then blocks. The token risk would be real and the benefit would be zero.

Use the scripts instead. They run where the cluster is actually reachable, keep the token out of your shell history and out of ps, and verify TLS properly. Then drop what they write onto the drop zone above. You can drop the whole output folder at once.

./scripts/acs_preflight.sh https://central-stackrox.apps.example.com
    tells you which server you are pointed at and what your token can read

export ROX_ENDPOINT=https://central-stackrox.apps.example.com
export ROX_API_TOKEN=<ACS API token>
./scripts/acs_pull_all.sh -o findings
    writes six files: alerts listed and hydrated, image CVEs for running
    workloads, image CVEs for everything else, node CVEs, and snoozed CVEs

./scripts/acs_pull_via_oc.sh          reaches Central through your oc session
.\scripts\acs_pull_over_ssh.ps1       PowerShell, through an SSH bastion

Then drag the findings folder here. Every file it contains is understood, and dropping several merges them rather than replacing: the alert list and the hydrated alerts are the same violations, so they are deduplicated and the one carrying violation text wins.

Image vulnerabilities

Deliberately kept out of the posture score above. The configuration posture has a fixed denominator derived from what was scanned, which is what makes the before and after numbers comparable. CVE counts change every time a vulnerability feed updates, with nothing in your manifests changing at all. Folding them together would produce a score that moves for reasons you did not cause and cannot act on, so these are reported separately.

Severity Priority CVE Component Fixed in Image Why it ranks here

Priority runs 0 to 15, not 0 to 10, because clamping to 10 would make every critical tie at the top and destroy the ordering exactly where it matters. It is CVSS plus named, bounded adjustments, all listed in the last column. It is not a CVSS score and should not be quoted as one.

Namespaces in scope

Unticking a namespace takes it out of scope: out of the findings, out of the score, out of the report and out of the JSON. It is not hidden, it is excluded, and the report says which namespaces were excluded and how many findings went with them. A score for a scope you chose is only honest if the document says what the scope was.

How do you want to work through these

Report only is the default, and nothing on this page will change a file until you move off it. That is deliberate. A remediation tool that can write before you have chosen to write is a new risk rather than a mitigation: the failure is not the tool doing something malicious, it is someone at the end of a long incident clicking the obvious button and producing a change to a production manifest they did not intend and cannot explain in review.

Every change is still previewed as a diff and still needs your confirmation. Nothing is applied to a cluster, no command is run, and no file on disk is modified until you download the result. Undo works one step at a time or all the way back.

Image vulnerabilities

Nothing on this panel is auto fixable, and that is the correct answer rather than a missing feature. ACS tells you a package is fixed in version X. It cannot tell you which image tag ships version X, because only your build knows that. The one real action here is replacing an image reference with one you supply, which is a text edit like any other and gets the same preview, confirmation and undo as every other fix on this page.

The worklist groups by image because that is the unit of work: you rebuild an image once and every fixable CVE inside it clears together. A list organised by CVE looks like progress and cannot be actioned.
