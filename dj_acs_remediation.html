Leave detail fetching on. GET /v1/alerts returns the slim ListAlert, which has a policy name and severity but no violation text. Only GET /v1/alerts/{id} returns the full alert with violations[]. Listing alone is why results can look empty.

CVEs are not policy violations and are not in /v1/alerts. This tab uses /v1/export/vuln-mgmt/workloads, which is where CVE data lives.
There is no automatic fix for a CVE, by design. ACS reports that a package is fixed in a given version. It cannot tell you which image tag contains that package, because that depends on how the image is built. Deriving one from the other would mean guessing, and a wrong guess points a production workload at a tag that does not exist or that quietly breaks it.

The token needs read on Image and Deployment. A token scoped only to Alert returns 403 here while the violations tab keeps working. You can also drop a .ndjson export from curl or roxctl onto the drop zone above.

How your token is handled. It stays in a variable in this tab for the duration of the request, then the field is cleared. It is never written to storage, never logged, and never included in any file you download. Use a short lived, read only, least privileged token regardless.

How do you want to work through these

Report only is the default, and nothing on this page will change a file until you move off it. That is deliberate. A remediation tool that can write before you have chosen to write is a new risk rather than a mitigation: the failure is not the tool doing something malicious, it is someone at the end of a long incident clicking the obvious button and producing a change to a production manifest they did not intend and cannot explain in review.

Every change is still previewed as a diff and still needs your confirmation. Nothing is applied to a cluster, no command is run, and no file on disk is modified until you download the result. Undo works one step at a time or all the way back.

Image vulnerabilities

Nothing on this panel is auto fixable, and that is the correct answer rather than a missing feature. ACS tells you a package is fixed in version X. It cannot tell you which image tag ships version X, because only your build knows that. The one real action here is replacing an image reference with one you supply, which is a text edit like any other and gets the same preview, confirmation and undo as every other fix on this page.
